# Блок-схема: Процесс составления рациона питания

## 1. Высокоуровневая схема всего процесса

```mermaid
flowchart TD
    A[Начало] --> B[Авторизация/Регистрация пользователя]
    B --> C[Вход в раздел 'План питания']
    C --> D{У пользователя есть<br/>настройки по умолчанию?}
    
    D -->|Да| E[Загрузка настроек:<br/>- Целевая калорийность<br/>- Цель: похудение/поддержание/набор<br/>- Бюджет: эконом/средний/премиум]
    D -->|Нет| F[Использовать значения по умолчанию<br/>2000 ккал, поддерживание, средний бюджет]
    
    E --> G[Пользователь может изменить параметры]
    F --> G
    
    G --> H[Указание предпочтений:<br/>- Любимые ингредиенты<br/>- Исключаемые ингредиенты]
    H --> I[Настройка приёма пищи:<br/>- Типы: завтрак/обед/ужин/перекус<br/>- Количество блюд на тип]
    I --> J[Нажатие 'Сгенерировать рацион']
    
    J --> K{Генерация плана}
    K --> L[Фильтрация рецептов по бюджету]
    L --> M[Исключение рецептов с<br/>нежелательными ингредиентами]
    M --> N[Распределение калорий по приёмам пищи]
    
    N --> O[Для каждого типа приёма пищи:<br/>- Расчёт целевых калорий<br/>- Подбор подходящих рецептов<br/>- Учёт цели пользователя]
    
    O --> P{Рецепты найдены?}
    P -->|Да| Q[Формирование недельного плана]
    P -->|Нет| R[Использование fallback-стратегии:<br/>- Универсальные рецепты<br/>- Любые доступные рецепты]
    R --> Q
    
    Q --> S[Отображение плана пользователю]
    S --> T{Пользователь доволен?}
    
    T -->|Да| U[Сохранение плана в БД]
    T -->|Нет| V[Перегенерация с теми же<br/>или изменёнными параметрами]
    V --> K
    
    U --> W[Генерация списка покупок]
    W --> X[Конец: план сохранён,<br/>список покупок готов]
```

## 2. Детальная схема: Алгоритм выбора рецепта

```mermaid
flowchart TD
    A[Начало выбора рецепта для приёма пищи] --> B[Получение всех доступных рецептов]
    B --> C[Фильтрация по типу приёма пищи:<br/>breakfast/lunch/dinner/snack]
    C --> D[Исключение уже использованных рецептов]
    D --> E{Цель пользователя}
    
    E -->|lose: Похудение| F1[Приоритет: goal_suitability='lose']
    E -->|maintain: Поддержание| F2[Приоритет: goal_suitability='maintain']
    E -->|gain: Набор массы| F3[Приоритет: goal_suitability='gain']
    
    F1 --> G[Этап 1: Рецепты с совпадающей целью]
    F2 --> G
    F3 --> G
    
    G --> H{Нашлись рецепты?}
    H -->|Да| I[Добавить универсальные рецепты<br/>goal_suitability='any']
    H -->|Нет| J[Этап 2: Использовать ВСЕ рецепты<br/>этого типа приёма пищи]
    
    I --> K{Цель = похудение?}
    J --> L{Цель = набор массы?}
    
    K -->|Да| M[Фильтрация: калории ≤ target × 1.3<br/>Сортировка по возрастанию калорий]
    K -->|Нет| N[Без фильтрации по калориям]
    
    L -->|Да| O[Фильтрация: калории ≥ target × 0.7<br/>Сортировка по убыванию калорий]
    L -->|Нет| N
    
    M --> P[Случайный выбор из кандидатов]
    N --> P
    O --> P
    
    P --> Q[Возврат выбранного рецепта]
```

## 3. Схема: Распределение калорий по приёмам пищи

```mermaid
flowchart TD
    A[Целевые калории дня] --> B[adjusted_calories = target_calories + 700]
    B --> C[Распределение по типам приёмов пищи]
    
    C --> D1[Завтрак: 25%]
    C --> D2[Обед: 35%]
    C --> D3[Ужин: 30%]
    C --> D4[Перекус: 10%]
    
    D1 --> E1[Калории на завтрак<br/>например: 2000 × 0.25 = 500 ккал]
    D2 --> E2[Калории на обед<br/>например: 2000 × 0.35 = 700 ккал]
    D3 --> E3[Калории на ужин<br/>например: 2000 × 0.30 = 600 ккал]
    D4 --> E4[Калории на перекус<br/>например: 2000 × 0.10 = 200 ккал]
    
    E1 --> F1[Количество блюд: N<br/>Калории на блюдо: 500 / N]
    E2 --> F2[Количество блюд: N<br/>Калории на блюдо: 700 / N]
    E3 --> F3[Количество блюд: N<br/>Калории на блюдо: 600 / N]
    E4 --> F4[Количество блюд: N<br/>Калории на блюдо: 200 / N]
```

## 4. Схема: Генерация списка покупок

```mermaid
flowchart TD
    A[Начало: план питания готов] --> B[Итерация по всем рецептам плана]
    B --> C[Получение ингредиентов рецепта]
    C --> D[Умножение количества на размер порции]
    D --> E{Ингредиент уже в списке?}
    
    E -->|Да| F[Увеличить количество]
    E -->|Нет| G[Добавить новый ингредиент]
    
    F --> H[Добавить в список покупок]
    G --> H
    
    H --> I{Ещё рецепты?}
    I -->|Да| B
    I -->|Нет| J[Финальный список покупок]
    J --> K[Отображение пользователю]
```

## 5. Схема: Взаимодействие с API Spoonacular

```mermaid
flowchart TD
    A[Нужен рецепт из API] --> B{Рецепт есть в локальной БД?}
    
    B -->|Да| C1[Перевод названия на русский]
    C1 --> C2[Поиск в Spoonacular по названию]
    C2 --> C3[Получение деталей рецепта]
    
    B -->|Нет| D1[Использование ID из запроса]
    D1 --> C3
    
    C3 --> E[Перевод ингредиентов на русский]
    E --> F[Перевод инструкций на русский]
    F --> G[Извлечение питательных веществ]
    G --> H[Формирование ответа]
    H --> I[Возврат данных на фронтенд]
    
    C2 --> J{Нашёлся?}
    J -->|Нет| K[Возврат ошибки 404]
    J -->|Да| C3
    
    E --> L[Обработка ошибок перевода<br/>max_retries=3]
```

## Ключевые компоненты системы:

1. **MealPlan** — модель плана питания пользователя
2. **MealPlanItem** — отдельные приёмы пищи в плане
3. **Recipes** — база рецептов с метаданными
4. **UserPreference** — предпочтения пользователя по ингредиентам
5. **UserSettings** — настройки по умолчанию
6. **ShoppingList** — список покупок
7. **generate_meal_plan** — основной алгоритм генерации
8. **_select_recipe_for_meal** — выбор рецепта для приёма пищи
9. **generate_shopping_list** — формирование списка покупок
